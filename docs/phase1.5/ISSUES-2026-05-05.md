## 詳細發現

### 🔴 #1 `model.Contest.State` 永遠是 zero-value（`/api/v4/contests` 列表沒 state）

**重現**：
```bash
$ curl -s -u "admin:..." "https://test-station.example.org/api/v4/contests" | jq '.[0]'
{
  "formal_name": "Demo practice session",
  "start_time": "2026-01-01T16:00:00+08:00",
  "end_time": "2026-01-01T18:00:00+08:00",
  "id": "1",
  "shortname": "demoprac",
  ...
}
# 注意：無 "state" 欄位

$ curl -s -u "admin:..." "https://test-station.example.org/api/v4/contests/2/state"
{"started":"2026-01-01T19:00:00.000+08:00","ended":null,...}
# state 是獨立 endpoint
```

**症狀**：
```
$ ./domjudge-tool import-users-teams ./new_users.csv --category-id 6
INFO router decision op=create-team-and-user path=api reason="default api-first"
import-users-teams: importer: cfg.contest_id is empty and no active contest exists; set contest_id in domserver.json
exit: 1
```
即使 contest 2 是 active（`/state.started=2026-01-01T19:00`、`ended=null`），`filterActiveContests` 仍回傳 0。

**根因**：
- `internal/model/contest.go:14` 宣告 `State ContestState `json:"state"``
- 但 `/api/v4/contests` list response 不包含 `state`（state 只在 `/api/v4/contests/{cid}/state` 獨立端點）
- `filterActiveContests` 讀 `contests[i].State.Started == nil` → 全部 nil → 0 active

**影響**：
- `cfg.contest_id == ""` 時 API create flow **永遠失敗**
- 唯一 workaround：手動編輯 domserver.json 加 `"contest_id": "2"`（且必須先有 #2 的 flag 才能由 CLI 寫進去）

**建議修法**：
- `filterActiveContests` 改用 `start_time` / `end_time` 比對「now」判定 active（時鐘需 server 同步），或
- 為每個 contest 額外打 `/api/v4/contests/{cid}/state` 取狀態（一次 fetch list，每個 cid 一次 GET — 對小 contest 數合理）
- 或同時提供：先嘗試讀 list 內 state（若有），fallback 用 start/end_time

### 🔴 #3 API create flow → user 連到錯誤的既有 team

**重現**（test station）：
```bash
$ cat /tmp/dj-p15-test/new_users.csv
username,email,affiliation,name
testapi001,testapi001@example.org,course001,測試甲
testapi002,testapi002@example.org,course002,測試乙

$ ./domjudge-tool import-users-teams ./new_users.csv --category-id 6
# 成功 exit 0
```

**實際結果**：
- ✅ teams.tsv 確實在 server 創建了 team id=54 (name="測試甲", group=6) 與 id=55 (name="測試乙", group=6)
- ✅ accounts.tsv 創建了 user id=55 testapi001 與 id=56 testapi002，密碼也正確（curl Basic Auth 登入成功）
- ❌ **但 user.team_id=1（DOMjudge admin team）與 team_id=2（Example team）— 連結到完全錯誤的既有 team**

**根因**：CCS `accounts.tsv` 規格沒有 `team_id` 欄位，user→team 連結是 server 端透過 username 或 name 匹配。我們的格式 `team\t{Name}\t{Username}\t{Password}` 中 Name 是 user 顯示名，與既有 team `name="DOMjudge"` 完全不同；server 沒有 ground truth → 落到某個預設 team（id 從 1 開始的 round-robin 或類似）。

teams.tsv 有 `teamID` 欄，我們填了 `Username`（如 "testapi001"），但這是 CCS public id，server 內部 team id 仍 auto-increment（54、55）。accounts.tsv 沒辦法 reference teams.tsv 的 teamID。

**影響**：
- API create path 看似成功但**資料完全錯位**
- 學生 user 會被誤分到 admin / dummy team，其 submission 跑到錯誤 team scoreboard 上
- 這是 v1.1.0 最嚴重的 silent corruption — exit 0 / out.csv 看起來正常但 server 端是壞的

**建議修法**（待 PR-0 demo 驗證 / DOMjudge 文件查證）：
- 方案 A：使用 DOMjudge 7 較新版本支援的 accounts.tsv `team_id` 欄（若存在）— 需查 `webapp/src/Service/ImportExportService.php`
- 方案 B：teams.tsv 改用 numeric teamID 與 accounts.tsv 的 username 完全一致；查 server 行為
- 方案 C：放棄 bulk accounts.tsv，改逐筆 POST `/api/v4/users/teams/{id}` PATCH（但 v7 沒有 PATCH，要 fallback scraper）
- 方案 D：在 teams 上傳後查 `/api/v4/contests/{cid}/teams` 拿到實際 team id，再透過 scraper update user 的 team_id（hybrid）

無論哪個方案，都需要 PR-0 idempotency probes 補做以驗證行為。

### 🟡 #5 `-v/-vv` 不影響 router 的 slog 行為

**重現**：
```
$ ./domjudge-tool -vv import-users-teams ./input.csv --category-id 6 2>&1
# 全部用 existing user（走 scraper 路徑）→ 沒任何 log 輸出
```

**根因**：`internal/cli/root.go:59-62` 把 logger 塞 ctx，但**沒有 `slog.SetDefault(logger)`**。`internal/importer/router.go:84` 的 `NewDefaultRouter` 用 `slog.Default()` — 拿到 Go 預設 logger（INFO level，handler 寫 stderr）。

實際表現：
- 預設 INFO 在不帶 `-v` 時就會印 router 決策（"INFO router decision …"）— 我在 testapi 那次有看到
- `-v`（INFO）和 `-vv`（DEBUG）對 router 沒影響
- DEBUG 級的 api 呼叫 telemetry（如有）也接不到

**影響**：無法用 `-vv` 看 API path 細節（ex: 哪些 org 被視為 missing、哪一筆 row 引發錯誤）。debug 體驗差。

**建議**：
- `root.go` 在建立 ctx logger 後同時 `slog.SetDefault(logger)`，或
- `NewDefaultRouter` 從 ctx 取 logger（但 router 介面目前沒收 ctx；要改 signature）

### 🟡 #7 DOMjudge 7 server `?team_id=` query 不過濾

**重現**：
```
$ curl -s -u developer:... "https://prod-station.example.org/api/v4/users?team_id=5" | jq 'length'
659   # 沒過濾，回全部
```

**根因**：DOMjudge 7.3.x server bug。`/api/v4/users` 的 `?team_id=` 參數沒被 server 端套用。**這不是 CLI bug**，但 CLI 的 `--team-id` flag 對 server 沒效果是 user-facing。

**建議**：
- 在 `cli/users/export_users.go` 收到 `--team-id` 時，client 端額外做 in-memory filter（防 server 不過濾的情況）
- 文件 changelog 補一行已知限制
