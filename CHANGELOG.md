## [Unreleased]

### Added

- `domjudge-tool web`: serve the local web UI directly from the CLI and
  open the user's default browser. Supports `--host`, `--port` (with `0`
  for an available free port), `--auth` (`token`, `basic`, `none`),
  `--token` / `DOMJUDGE_TOOL_WEB_TOKEN`, `--username`, `--password` /
  `DOMJUDGE_TOOL_WEB_PASSWORD`, `--tls-cert`, `--tls-key`, `--no-browser`,
  and `--db`.
- Security controls for the local web UI: constant-time token/basic auth,
  DNS rebinding check on loopback listeners, CSRF state-changing request
  rejection via `http.CrossOriginProtection`, loopback-only restriction for
  `--auth none`, and standard security headers.
- Zero-dependency one-line copy-paste installers for all platforms:
  `scripts/install.sh` for macOS/Linux (POSIX `sh` with `curl` or `wget`)
  and `scripts/install.ps1` for Windows (built-in PowerShell 5.1+ and
  PowerShell 7). Both verify SHA-256 checksums from `checksums.txt`, install
  user-level binaries without elevation, and update user PATH.

### Changed

- Web UI packages moved from `internal/desktop/*` to `internal/webui/*`
  (assets, db, handler, oplog, profile, settings, templates).
- `internal/webui/server` composes the HTTP server, SQLite stores, security
  middleware, and operation execution.
- `internal/webui/assets/desktop.css` renamed to `webui.css` (served at
  `/static/webui.css`). CSS rebuild task renamed to `mise run build-css`.
- Output directories in problem and submission download forms are now typed
  directly rather than selected via native server-side directory dialogs.

### Removed

- Native Desktop application (`cmd/desktop`, `cmd/package-desktop`,
  `cmd/cli-launcher`, `internal/desktop/cliinstall`, Wails v3 beta dependency,
  and native CGO/GUI build requirements).
- Desktop release bundles, desktop-specific CI workflows, and unsigned native
  desktop artifacts.
- Command-Line Tool installation card in Settings and `/api/pick-directory`
  dialog endpoint.

## [1.7.0] - 2026-10-24

First release with the native Desktop app and automated, verifiable
release artifacts. The CLI's commands, flags, output files,
`domserver.json` schema, and CSV column order are unchanged.

> **Building from source now requires Go 1.27.3 or later.** Contributors
> install every pinned runtime and tool with [mise](https://mise.jdx.dev/);
> the Justfile is gone.

### Added

- Native Desktop app (Wails v3 preview) for macOS, Linux, and Windows on
  amd64 and arm64: server profiles, user/team import and removal with
  live progress, export users, set password, problem download and import,
  scoreboard and submission download, account email tools, settings, and
  operation History. Profiles are stored locally and are separate from
  the CLI's `domserver.json`.
- Desktop bundles include the independent CLI. **Settings → Command Line
  Tool** installs, relinks, or removes a current-user `domjudge-tool`
  command without editing PATH, shell configuration, or the registry.
- Release assets: six CLI archives with `checksums.txt`, six Desktop
  bundles with `.sha256` files, and a build-provenance attestation for
  every archive (`gh attestation verify <archive> --repo
  ntub/domjudge-tool`).

### Changed

- Releases are published only by GitHub Actions from an annotated
  `vMAJOR.MINOR.PATCH` tag on `main`, with these notes taken from this
  file.
- Contributor tooling moved from `just` to `mise`; `mise.lock` pins
  checksums for every tool on six platforms, and CI installs from it.
- Open Dependabot alerts are summarized in one issue per month; no
  automated dependency pull requests are opened.

### Security

- Go 1.27.3 fixes GO-2026-6809 (`crypto/x509`). Dependency upgrades fix
  GO-2026-5025 to GO-2026-5030 (`golang.org/x/net` v0.61.0),
  GO-2026-5970 (`golang.org/x/text` v0.43.0), GO-2026-5841
  (`klauspost/compress` v1.20.3), and GHSA-vfj7-8cjw-p6xm in the
  Desktop CSS build (`@parcel/watcher` 2.6.0).
- Desktop bundles are unsigned and not notarized; verify downloads with
  the published checksums and attestations.

## [1.5.0] - 2026-06-04

Phase 2 — DOMjudge 8.3.1 support. One binary now serves both
DOMjudge 7.3.x and 8.3.1 servers, selected by the existing `version`
field in `domserver.json`; existing 7.3.x configs load and behave
unchanged.

### Added

- DOMjudge 8.3.1 web gateway routing via
  `internal/client/web/gatewayfactory`, keeping the version-specific
  scraper behind the shared gateway interface.
- `internal/client/web/v8`: a full DOMjudge 8.3.1 jury scraper for every
  Gateway operation, including problem ZIP download, user/team delete,
  and create / update / password / email / affiliation flows. The
  implementation handles the v8 form deltas: `create-new-user`, team
  penalty, no CSRF token, team-view user-id selector, and affiliation
  list column order.
- `internal/client/api/v4` cross-version response decoding so the same
  REST client handles DOMjudge 7.3.x and 8.3.1, including API version
  fields and integral problem time limits serialized differently by
  8.3.1.

### Changed

- On DOMjudge 8.3.1, `import-users-teams` routes create, update,
  password, email, and affiliation changes through the scraper. Delete
  remains scraper-only because 8.3.1 exposes no REST API DELETE for
  users or teams.
- CLI command names, flag names, output file names, and the
  `domserver.json` schema are unchanged; there are no breaking changes
  for existing DOMjudge 7.3.x users.

### Fixed

- `set-password` on a v8 config without `--user-roles` now uses the
  scraper instead of an unsafe bulk accounts import. The v8 REST
  PUT-update path is broken, so this avoids dropping account data through
  the wrong backend.

### Notes

- No behavior change yet: single-entity `POST /api/v4/users` on
  DOMjudge 8.3.1 was verified to honor email, team linkage, password,
  and roles, and could back v8 user-create in a later release.

## [1.4.0] - 2026-06-03

Phase 1.5 — post-release hardening from live DOMjudge 7.3.x validation.
Two tracks: `download-scoreboard` now matches the Phase 1 / Python cell
format and exports **every** team category (ADR 0007), and
`import-users-teams` resolves affiliations through a cache and returns a
structured per-run report.

> **Scoreboard CSV schema change.** `download-scoreboard` output is no
> longer byte-identical to v1.3.x: a new `Category` column is inserted
> after `Score`, hidden categories are now included by default, each
> sortorder section restarts at `rank = 1`, and the trailing summary row
> is gone. Pass `--exclude-hidden` to drop hidden-category rows. See
> `docs/adr/0007-scoreboard-cell-format-and-categories.md` for the
> rationale and the full before/after.

### Added

- `download-scoreboard --exclude-hidden` (default `false`) — drops rows
  whose matching team-category group has `hidden = true`. Omitted, every
  category (including the built-in `System` group) is exported.
- New `Category` column in the scoreboard CSV, inserted after `Score`
  and before the problem columns, sourced from the group matching each
  row's sortorder section.
- `importer.ImportUsersTeamsWithReport` returns an
  `ImportUsersTeamsResult` / `Summary` (created / updated / skipped
  counts plus affiliation-fallback tallies); `import-users-teams` prints
  this summary on completion.

### Behaviour changes (visible)

- Scoreboard solved/tried cells are restored to the Python format —
  `"<time>/<tries> try(ies)"` for solved, `"<tries> try(ies)"` for
  tried-but-unsolved (`tries = num_judged + num_pending`), empty for
  untried — replacing the v1.3.x `"<num_judged> <time>"` regression.
- `download-scoreboard` issues one `/scoreboard` request per populated
  sortorder (`?sortorder=N&allteams=true`) instead of a single default
  call, so hidden and higher-sortorder categories are no longer dropped.
- The scoreboard summary row (`%d///%d`) is no longer emitted.

### Internal

- `internal/scoreboard`: `formatScoreCell` rewritten; `Download`
  enumerates distinct populated sortorders; `Build` resolves each row's
  category against its sortorder group rather than `GroupIDs[0]`; a
  cross-path `Build`-vs-`Parse` equivalence test guards the cell format.
- `ScoreboardListOpts` gains a `SortOrder *int` field.
- `internal/importer`: new `affiliationResolver` caches organization
  lookups and tracks name-fallback hits; the create flow and CLI wiring
  switch to the reporting variant.

## [1.3.0] - 2026-05-07

Phase 1.5 — operator UX. Long-running batch commands now show a
single-line progress bar on stderr, gated by a persistent
`--no-progress` flag plus `NO_COLOR`, `TERM=dumb`, and TTY detection
so pipes stay byte-identical to v1.2.x output. Bundles two ctx
cancellation parity fixes spotted while preparing the rollout.

### Added

- All seven long-running batch commands gain a stderr progress bar:
  `import-users-teams`, `send-user-accounts`, `render-user-accounts`,
  `download-problems`, `download-submissions`, `download-scoreboard`.
  The bar disappears in non-TTY pipelines automatically; pass
  `--no-progress`, set `NO_COLOR=1`, or set `TERM=dumb` to force-
  disable on a TTY.
- New persistent flag `--no-progress` on the root command (default
  `false`).

### Internal

- New leaf package `internal/util/progress` exposing the small
  `Reporter` interface (`Start` / `Tick` / `Finish`) plus `New` and
  `Nop` constructors. The visual implementation wraps
  `github.com/schollz/progressbar/v3` (first runtime dependency added
  since project bootstrap; transitive: `mitchellh/colorstring`,
  `rivo/uniseg`, `golang.org/x/sys`, `golang.org/x/term`).
- `internal/cli/context.go` exposes `WithReporter` /
  `ReporterFromContext`; the latter falls back to `progress.Nop()` so
  library callers can `Tick` unconditionally without nil-checks.
- `ImportOptions.Reporter`, `SendOptions.Reporter`, and
  `submissions.Options.Reporter` accept an opaque `progress.Reporter`
  so library packages remain print-free; only the CLI root PreRunE
  constructs a real bar.

### Bug fixes (P1)

- `render-user-accounts` and `download-scoreboard` cli loops now
  honour `ctx.Done()` between rows, matching the `download-problems`
  / `download-submissions` precedent and `docs/CONVENTIONS.md`
  "Honour `ctx.Done()` in long-running loops".

### Behaviour changes (visible)

- Stderr now emits a progress bar on a TTY for the seven batch
  commands. Stdout (the data path) is unchanged. `2>/dev/null`,
  `--no-progress`, `NO_COLOR=1`, and `TERM=dumb` each suppress the
  bar.

## [1.2.1] - 2026-05-07

Phase 1.5 — patch release. Auto-recovers `import-users-teams` UPDATE
when the v7 `/api/v4/users` snapshot returns `team_id == nil` for an
existing user — a state left behind by users orphaned during the
v1.1.0 silent-corruption bug (fixed in v1.1.1). Operators no longer
need `--delete-existing` or web-UI intervention to re-sync those rows.

### Bug fixes (P0)

- `import-users-teams` UPDATE path now performs a two-step team-id
  lookup when the API list snapshot omits `team_id`: first GET
  `/api/v4/users/{id}` (singular endpoint, may populate when list
  doesn't), then GET `/api/v4/contests/{cid}/teams` matching by
  `name` OR `display_name`. Falls back to the new `web.ErrTeamIDMissing`
  sentinel — wrapped with the offending username — when both lookups
  fail, replacing the cryptic `web: update team: TeamID is required`.

### Internal

- New `web.ErrTeamIDMissing` sentinel, `errors.Is`-comparable.
- New `internal/importer/team_lookup.go` with `resolveTeamID` helper.
- `internal/importer/importer.go` UPDATE path adds a nil-`TeamID` guard
  before `gw.UpdateTeam`.

### Behaviour changes (visible)

- None for the happy path; failing rows surface a clearer error.

## [1.2.0] - 2026-05-06

Phase 1.5 — email template tooling: offline scaffold, validate, and
per-recipient render-to-disk for the credential mailer flow.

### Added

- `email-template-example [-o <dir>] [--force]` — scaffold a template
  directory with subject + text/HTML body containing all six allowed
  placeholders. The scaffolded files pass `email-template-validate`
  immediately (round-trip guarantee).
- `email-template-validate <dir>` — verify a template directory loads
  correctly and uses only the fixed placeholder set (username, name,
  email, affiliation, password, server_host).
- `render-user-accounts <csv> <template-dir> [-d <output-dir>]
  [--from-email <addr>] [--force]` — offline render of per-recipient
  `.eml` files (RFC 5322), parallel to `send-user-accounts` but never
  touches SMTP. Requires a loaded `domserver.json` (for `$server_host`).

### Internal

- `internal/email.BuildEML` extracted; `SendUserAccounts` now delegates
  its message construction to it (zero behaviour change for the SMTP
  path).
- `internal/email` exposes test seams `nowFn` / `randRead` (package-
  level vars) for deterministic golden tests of RFC 5322 output.
- `internal/email.WriteTemplateScaffold` and sentinel
  `ErrTemplateDirExists` added.

### Behaviour changes (visible)

- None for existing commands.

## [1.1.1] - 2026-05-05

Hot-fix release after live validation against the production DOMjudge 7.3.4
test station and production server. v1.1.0's API create flow had
multiple silent-corruption paths on real v7 servers; v1.1.1 reverts
the create transport to the v1.0.0 scraper while keeping the resource
clients in place for Phase 2 / DOMjudge 8. CLI flags and output
formats are unchanged from v1.1.0.

### Bug fixes (P0)

- `import-users-teams` create cohort no longer hits the API on
  DOMjudge 7. The `accounts.tsv` linkage runs through a username
  regex + Doctrine `Team::find($pk)` lookup with no team-id column,
  so v1.1.0 silently linked new users to small-id existing teams
  (admin / Example). `OpCreateTeamAndUser` now returns
  `path=scraper reason="accounts.tsv user→team linkage broken on v7"`.
- `filterActiveContests` derives activeness from `start_time` /
  `end_time` instead of the nested `state` object, which the v7
  `/api/v4/contests` list response does not carry. The auto-pick path
  now works on every shipping v7.3.x server.
- `gen-config` learned `--contest-id <id>`; new users no longer have
  to hand-edit `domserver.json` after running it.
- `dedupeMissingAffiliations` now trims whitespace before comparing,
  defending against CSV parsers that leave `\r` / NBSP on the last
  column. Live v1.1.0 logs showed duplicate organization rows that
  the byte-exact predicate should have deduped; pending live confirm.

### UX & observability fixes (P1)

- `-v` / `-vv` now also rebinds `slog.SetDefault`, so router decisions
  and importer dedup debug lines respect the verbose level.
- `import-users-teams` prints
  `Imported N users (created C, updated U, skipped 0).` on success.
- `gen-config` prints `Wrote <path>.` on success.
- `export-users --team-id` re-filters in memory, working around v7's
  ignored `?team_id=` query parameter (server-side bug, not CLI).

### Documentation

- `docs/phase1.5/PR-2-scoreboard.md` — fixed CSV header spec drift;
  the implementation has always used the 5-column title-case shape
  (`Rank,TeamAffiliation,TeamName,SolvedCount,Score,...`), the spec
  draft accidentally documented a 6-column lower-case header.
- ADR 0006 + `docs/phase1.5/SPEC.md` note the v7 accounts.tsv
  linkage quirk and defer API create to Phase 2 / DOMjudge 8.

## [1.1.0] - 2026-05-05

Phase 1.5 — switch internal operations from HTML scraping to the
DOMjudge native REST API where supported. CLI flags and output formats
are unchanged; this is an internal refactor delivered as a minor
version bump.

### Internal

- New `internal/client/api/v4.ImportsResource` wrapping the bulk
  import endpoints
  (`POST /api/v4/users/{groups,organizations,teams,accounts}`,
  `POST /api/v4/contests`, `POST /api/v4/contests/{cid}/problems`).
- New `OrganizationsResource`, `GroupsResource`, `ContestsResource`,
  and `ScoreboardResource` wrapping the corresponding read endpoints.
- New `internal/importer.Router` chooses between API and scraper
  per operation; emits structured `slog` decisions
  (`router decision op=… path=… reason=…`) for incident triage.
- `download-scoreboard` now drives the JSON scoreboard endpoint and
  reconstructs the CSV client-side from `/contests/{cid}/scoreboard`,
  `/contests/{cid}/teams`, and `/contests/{cid}/organizations`
  (byte-identical to v1.0.0-rc1 output for the same `--cid`).
- `import-users-teams` create-flow drives `Imports.Teams` /
  `Imports.Accounts` / `Imports.Organizations`. Per-row email and
  role-aware password updates remain on the v7 scraper for parity
  (the CCS `accounts.tsv` schema has no email or role columns).
- `set-password` defaults to the API path; falls back to scraper when
  `--user-roles` is supplied.
- `web.Gateway` retains 11 methods; 6 are now marked
  `// Deprecated:` but still implemented for fallback.

### Behaviour changes (visible)

- **`import-users-teams` no longer silently picks a contest when
  `domserver.json.contest_id` is empty.** With exactly one active
  contest the previous behaviour is preserved (auto-select). With
  zero or multiple active contests the command now errors with
  `cfg.contest_id is empty and N active contests exist (...); set contest_id in domserver.json`.
  Rationale: the v7 web UI accepted an empty `domjudge_cid` cookie
  and let the server choose; the API has no such fallback.
- **`download-scoreboard` now requires Basic Auth credentials.**
  Phase 1 fetched the public `/public?static=1` page anonymously;
  v1.1.0 calls `/api/v4/contests/{cid}` and three sibling endpoints,
  all of which require credentials. Missing or wrong credentials
  surface as a config error before any HTTP traffic, so this is not
  a breaking change for users with a populated `domserver.json`.

### Configuration

- New optional `domserver.json` field `prefer_scraper` (bool,
  omitempty). When `true`, all hybrid operations route through the v7
  scraper, ignoring the API path. Existing `domserver.json` files
  without this field load unchanged and behave as `prefer_scraper:
  false`.

### Docs

- New `docs/phase1.5/` directory: SPEC, PLAN, CONTRACT, per-PR specs
  (PR-0..PR-5).
- New ADR 0006 (`docs/adr/0006-api-first-with-scraper-fallback.md`,
  Status: Accepted on 2026-05-05) records the decision to keep
  `web.Gateway` for delete and problem-ZIP flows that have no v4 API
  equivalent on DOMjudge 7.3.x.
- `docs/ROADMAP.md`, `docs/ARCHITECTURE.md`, `docs/PHASE1.md`,
  `docs/CONVENTIONS.md`, and `docs/TESTING.md` updated to reflect the
  hybrid architecture and the contract-test layer.

### Locked decisions preserved

- Python `services/web/v7.py:161` inverted-filter QUIRK on the delete
  flow stays locked verbatim — Phase 1.5 does not migrate delete, so
  the QUIRK and its named regression tests
  (`TestDeleteUsers_PythonInvertedFilter_LocksKnownQuirk`,
  team variant) remain authoritative.
- `domserver.json` schema is backward-compatible (only one new
  optional field, see Configuration above).
- `import-users-teams.csv` column order and the Python golden output
  for `gen-config` and `import-users-teams-example` are unchanged
  (byte-identical anchors still pass).
